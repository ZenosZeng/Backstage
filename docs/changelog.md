# 版本记录

[返回 Backstage 首页](../README.md)

本文集中保存发布级变更和升级注意事项，不逐条复制 Git 提交。README显示最新版本号，并保留当前major/minor功能版本的主要feature；patch修复不会替换该摘要。
版本记录按新到旧排列，与 `pixi.toml` 中的当前版本保持一致。

这是本工作区的功能版本约定，不等于任何单个脚本的接口版本，也不表示已创建同名 Git tag。

开发分支、PR和发布流程见 [开发与版本管理](development.md)。

- 修复独立审计确认的 10 项问题：约束评测文档写入路径、校正空预期负例判定；补齐 CLI 生命周期依据、状态及省略提示；自检识别循环链接并遵守 `--local-root`；空文档查询、损坏 raw 和无配置副本仍可按各自范围检索；缺失 Git 不再误报任务不存在；Unicode 展开后的摘录保留命中内容。
- 修复 PR 复审的边界问题：基线评测使用指定版本的完整脚本模块；共用配置校验拒绝空工作区路径和畸形项目项；配置损坏时独立检索明确告警后按原词读取；评测运行错误统一退出 2，避免 traceback 与失真得分。Windows 补丁按内容识别合法的 Prompt 文件副本，保持 Linux 的链接校验规则。
- 补齐复审发现的验证遗漏：严格加载统一校验别名；评测预先校验评分字段、CLI 参数及事件数据，拒绝空用例集，两侧子进程使用一致的模块隔离；断链配置明确告警。保留离线工作区浏览及合法空查询、选项形态文本查询的行为。

升级：无需迁移 raw、任务状态或本机配置。别名为可选项，未配置时维持原词匹配；文档搜索使用独立 `--documents` 模式，不接受事件筛选。应用版本变更不自动部署、重启服务或发布标签。Windows out-of-tree 补丁已刷新到本版上下文并验证应用/回退；Windows 实机验证仍仅覆盖 v0.6.1，见 patches/README.md。

## v0.6.1 · 2026-10-16

- 新增 [`patches/`](../patches/README.md)：Windows 可运行补丁。补丁**不进 `main`**，只在
  Windows 机器上按需 `git apply`，`main` 的代码与 Linux 线上行为都不变。
- 补丁覆盖四类改动：缺少 `fcntl` 时用 `msvcrt` 实现文件锁；识别 junction 等 reparse
  point，无符号链接权限时按目标类型降级（目录用 `mklink /J`，文件用复制）；子进程统一
  按 UTF-8 解码，避开中文 Windows 默认 GBK 导致的静默解码失败；`os.replace` 在
  WinError 5 下短暂重试，避免同步停在“部分内容已替换”的状态。
- 应用后 `tests/` 全量 86 项在 Windows 上连续 3 轮通过；修复 `os.replace` 之前，
  `test_sync` 6 轮里 5 轮有失败且每轮用例都不同。Linux 未实测，对 Linux 无行为影响的
  结论来自代码审查。`tools/` 下的服务部署在 Linux，不在补丁范围。

## 升级注意事项

- **v0.6.0**：先 `pixi install --locked` 安装新增 Markdown 渲染依赖，再用 `pixi run web`
  启动工作台。默认地址 `127.0.0.1:8787`，远程访问需端口转发；读取快照最多复用 3 秒。
  既有记忆与飞书会话无需迁移，详见 [工作台说明](../tools/web/README.md)。
- **v0.5.1**：从旧版首次升级飞书桥时，在宿主机用 `claude-feishu --stop` 后重新
  启动一次，以清除旧进程已注入的凭据环境；后续可正常使用 `/restart`。
  若从凭据文件删除白名单且没有调用者显式白名单/开放模式，新配置会拒绝启动或重载；
  重载校验失败保留旧服务，撤销旧访问应显式停止服务。
  B1K 进程需带与当前 Config 相符的 `--config`，相对路径按进程 cwd 解析；
  非标准包装器应保留此参数。B1K 待发告警只在当前进程中重试，重启不保证补发；
  训练待发事件保存在既有游标文件。事件 schema 和飞书会话格式不变。
- **v0.5.0**：记忆事件仍使用 `schema_version=1`，飞书会话仍为 v2，无需迁移数据；
  更新代码后用现有飞书 `/restart` 或标准脚本重载 bridge。原生训练通过本机
  `native_runs` 接入，修改配置后重载 watchdog；监控重载不启停训练或 producer。
  公共工作区模板用于新建工作区，已有 Skill/Prompt/知识应按需合并。
- **v0.4.0**：会话文件升 v2 —— chat 保存目录与 harness，`sessions.claude` / `sessions.dsh` 分别保存原生会话 ID 与累计统计；首次读取 v1 时保留权限 0600 的 `sessions.json.v1.bak` 并原子写入 v2，不保存聊天正文。尚不支持重启请求的旧 daemon 首次升级需在宿主机停起一次，避免持有 v1 状态的旧进程覆盖 v2；本版之后使用飞书 `/restart` 或标准脚本请求原服务自行重载。回滚代码可以启动，但旧代码读不到嵌套会话 ID，需停服务并从 `.v1.bak` 恢复才能找回迁移前的 Claude 上下文。DSH 是可选依赖，未安装时 `/dsh` 拒绝切换而 Claude 继续可用；其权限、限制与部署细节见 [DSH harness 参考](../tools/claude_feishu/README.md)。
- **v0.3.0 发布前审计修复**：生命周期引用校验统一到追加、导入、校验与同步，禁止普通事件取代任务状态；`audit` 补齐独立状态 head 冲突检查。忽略本机配置备份。遥控 `progress_interval_seconds` 真正控制流式卡片（默认 5 秒，0 关闭中间刷新）；旧配置值 600 现在会生效，需按实际需求调整后重启。新增 13 项回归，测试由 177 项增至 190 项。
- **v0.3.0**：各机器升级公共核心后才能使用 `brief/task`；只同步 S3 Skill 不会安装新 CLI。raw 数据 `schema_version=1` 不变，无需迁移历史；旧客户端可读取状态决定，但不会执行生命周期筛选。搜索文本默认改为相关性短摘要，`--sort recent --full` 恢复时间倒序全文，JSON 保持完整事件。
- **v0.2.3**：`resolve-shared` 拒绝内容回退时，先核对冲突快照并合并，不要删基线或用 mirror 绕过检查。详见 [Shared 分叉保护](memory.md#shared-分叉保护)。
- **v0.2.1**：目录重排需要各机器先升级 CLI 再同步；历史事件保留写入时的路径。详见 [存储边界](memory.md#存储边界)。

旧版本号映射只用于 2026-09-14 之前的记忆事件与广播；2026-09-28 的 v0.3.0 是新版本，不适用旧号映射。
