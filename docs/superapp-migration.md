# Agent 工具工作区迁移

本文说明将独立记忆、监控和飞书遥控工具收纳到 `.agents` 的通用流程。
它是迁移参考，不代表新克隆的工作区已部署服务或完成验收。

## 目标与边界

- Memory、共享文档和工具源码统一由 `.agents` 管理；已有 S3/JSON 数据按自身格式保留。
- 监控公共核心维护轮询、通知和服务管理；项目解析与阈值放在本机 Git 忽略的 adapter 中，业务仓库不再维护第二套运行入口。
- 飞书遥控保留白名单、防重放、会话映射、超时和进程组清理；新机器默认只读，需要更高权限时由用户明确配置。
- 各工具独立进程、独立配置和运行状态；监控不启停业务训练、仿真、推理或评分。
- 工具及环境锁走 Git；私有配置、凭据、PID、日志、游标不进公共 Git 或 S3。
- 使用 Pixi 安装与启动，不借用业务仓库 Python 或 `pip --target deps`。

## 迁移步骤

1. 核对当前工作树、配置、状态文件和服务身份，保留已有业务改动。记录哪些工具实际运行，避免把旧 PID 或磁盘文件当作服务已更新的证据。
2. 安装 `.agents` 工具核心，在本机准备私有配置。业务监控按 [Watchdog 接入说明](../tools/watchdog/README.md)提供 adapter；未安装的 adapter 不随公共 Git 自动补齐。
3. 对照已有配置整理新路径，先用 `--once --no-notify` 检查配置和只读状态。集群的 `--once` 只读取已有快照，不验证 SSH 连接；遥控的 `--once` 不连接飞书或执行 Agent。
4. 明确部署后，停止旧消费者，再迁移会话映射、防重放状态或监控游标。先保留备份，不让旧、新服务同时写同一状态文件。
5. 启动新服务，核对进程身份、启动版本、就绪状态和实际采样时间。飞书 bridge 需确认连接就绪；监控需确认新快照及错误状态，而不是只看启动命令退出码。
6. 验收后归档旧独立仓库并保留 Git 历史、原状态备份；移除旧运行入口，避免出现两个活跃实现。公共代码由 Backstage 维护，业务 adapter 继续仅在本机维护。

集群采集的单独切换步骤见 [集群监控迁移](../tools/cluster/README.md#从独立-cluster-monitor-迁移)。
共享知识、Skill 和 Prompt 的修改仍按[共享同步规则](memory.md#shared-分叉保护)处理，
迁移工具代码不自动授权覆盖共享内容或发布真实项目资料。

## 验证策略

- 用临时目录、合成日志和 mock 检查状态解析、配置校验、告警去重与恢复，不需要加载模型或业务环境。
- 飞书网络通过 mock 验证；发送真实卡片或代发 Agent 请求需要按实际使用范围授权，离线测试不等于真实连接验收。
- 启停检查应核对进程身份、单实例和子进程清理，不用宽泛 `pkill` 停止无关服务。
- 迁移会话和游标时核对文件内容与权限，不打印秘密；确认新服务加载正确来源后再整理旧文件。
- 迁移监控不启停被观察的任务，不更改远端训练或评测配置；远端只提供可访问的状态或日志，无需另部署 watchdog。

Git 更新、S3 同步和服务部署是独立操作。更新源码不自动迁移配置、重启服务或授予更高权限；
提交、推送和部署分别遵守当前工作区授权规则。
