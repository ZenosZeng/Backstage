# Backstage 只读工作台

在已有工作区中启动：

```bash
pixi install --locked
pixi run web
```

打开 `http://127.0.0.1:8787`。服务在前台运行，按 Ctrl+C 停止；自定义端口用
`pixi run web --port 8788`。首次使用需先完成 [本地工作区初始化](../../examples/README.md)。

远程工作区通过 SSH 或 Coder 将端口转发到访问者电脑；例如在电脑上运行：

```bash
ssh -N -L 8787:127.0.0.1:8787 <workspace-host>
# 或使用已登录的 Coder CLI
coder port-forward <workspace> --tcp 8787:8787
```

随后在电脑打开同一个本机地址。MVP 仅监听 127.0.0.1，并检查 Host；不提供公开访问、
登录系统或任意域名代理。私有记忆、项目文档及配置不打包进静态资源，也不发布到托管网站。

## 页面

- 项目时间线是首页：每个业务项目一条横向时间条，默认看完整历程，也可切换月、周刻度；支持按项目名称、简介和关联任务状态筛选。点击项目查看关键历程，再按需展开任务时间线；历史任务较多时默认折叠，图表内部可滚动。点击任务聚焦其关键节点。
- 项目详情按时间展示决策、验证、修复、风险与生命周期变化；中间节点可折叠，来源和验证依据按需打开，不再把原始记忆列表作为主要页面。项目知识和报告入口跟随项目。
- 业务归属优先采用事件显式 `business_projects`，缺失时继续来自 `.share/knowledge/projects/*.md` 和同名 JSON 的来源关联，延续明确唯一的 task 或项目命名空间；不按重叠仓库标签扩散。没有项目知识的工作区明确标为来源仓库视图。
- 文档按项目阅读知识、报告和架构图，也可查看全部文档；支持正文检索、Markdown 表格、相对链接及受限 SVG 预览，保留原有目录安全边界。
- “监控”分为集群资源、训练与评测、本机服务三个子页：集群资源展示独立采集器保存的多机资源快照；训练与评测沿用已配置 watchdog 的只读查询；本机服务展示进程、版本和工作区自检。页面不启停任务或服务，区分未配置、不可用、无数据和已有结果。

时间条表示**已有记录的首尾跨度**，不等于真实工期、计划排期或连续工作时长。任务状态只来自明确生命周期声明；未声明和冲突分别展示。不会因关联任务全部关闭而推断整个项目完成，也不用文件修改时间补造项目起点。日期刻度采用 UTC。

只读 `/api/timeline` 返回项目摘要，`?project=slug` 返回项目任务与关键节点，附加 `&task=id` 聚焦某任务。关键节点最多 40 个，覆盖首尾，给出省略数量。无记录项目仍可阅读知识，日期显示暂无记录。旧记忆/交接 API 保留供已有消费者使用。

首页统计、日期和任务状态从同一次时间线快照计算，跨项目任务按 ID 去重；搜索、状态筛选仅改变可见项目，统计注明“当前全部项目口径”。未声明、暂停、冲突及未归属记录单独说明，旧 `-` 不计作业务任务。“需要关注”展示明确状态冲突、未决风险及新鲜的 Agent 等待或错误，有项目/任务入口，不据 `active` 推断正在运行。

聚焦任务后，先看最近决策、验证成果和待核对事项，再展开会话标识与原始依据。会话显示 Agent、机器、原生 ID 和关联来源；执行观测带时间，五分钟后未知，各会话观测分别保留。页面没有新的会话执行、聊天转存或网页遥控入口。

任务内“生成交接摘要”读取 `/api/handoff?task=id&to_agent=claude`，可复制给接收 Agent；结果明确已准备、未派发，保留生命周期及执行观测依据。“准备记忆审查”读取 `/api/review?task=id`，复制有数量与整包字符预算的材料，由当前 Agent 做语义检查，页面不会把材料准备成功当成审查通过。

文档列表和预览显示来源核验状态，可展开来源提交、覆盖路径、验证时间及事件依据。覆盖源码变化、相关新记录与信息不足分别提示，不把文件 mtime 当核验时间。配置和语义说明见 [记忆参考](../../docs/memory.md#任务上下文与知识核验v0110)。

页面由纯 HTML/CSS/JavaScript 组成，不需要 Node/npm 或前端构建。Python 标准库提供
本机 HTTP 服务，`markdown-it-py` 负责文档渲染；通过原有 Pixi 环境安装。

右上角太阳/月亮按钮可切换深浅色模式。首次打开跟随系统偏好，手动选择保存在当前
浏览器的 localStorage，刷新及再次打开时保留；记忆、任务和运行模块在两种模式下
保持紫、暖橙和蓝青的区分。

## 数据与时间

点击右上角刷新，页面不启动采集器，也不通过 SSH 临时采集。总览、记忆和文档目录共享同一个进程内快照，
TTL 为 3 秒；过期后的并发请求只重建一次，事件、任务状态、业务关联与目录一同更新，
不维护额外查询缓存或持久索引。页面标明采样时间，刷新最多仍可能复用 3 秒内的快照。
正文采用 13–14px，主要辅助信息采用 11–12px；深浅两种主题和手机布局均需浏览器验证。

项目、文档、训练与评测、本机服务按需手动刷新；集群资源页每 3 秒读取已保存的采集快照，
离开该页后停止读取。“暂停画面”只暂停浏览器更新，后台采集器继续运行；采集节奏不由页面控制。

记忆来源机器只显示最后事件时间，
不能据此判断在线状态；`shared 基线`是本机同步基线目录更新时间，不是 raw 同步成功时间。
任务的 `unknown/conflict` 如实展示，不从旧待办推断任务仍在进行。

集群数据来自本机 `.local/tools/cluster-monitor/snapshot.json`，由单独启用的采集服务更新；
网页请求只读该文件，不连接远端、不探活端口。页面读取时间与采样时间分开显示，过期、
采集失败或缺失的快照不冒充当前状态。训练/评测仍只读取本机配置可访问的环境，不提供历史训练曲线。
数据校验失败会提示部分数据不完整。

可指定其他已有工作区：

```bash
pixi run web --root /path/to/.agents --local-root /path/to/.agents/.local
```

`--root` 控制记忆和文档来源，`--local-root` 控制本机配置/服务记录来源。读取业务监控
仍使用当前工具核心的 `--once` 实现；集群仅读取 `--local-root` 下的采集快照。工作台没有修改记忆、编辑文档或网页遥控接口。

## 集群资源快照

每台机器的 GPU 卡片固定一行八张，窄屏下调整卡内排版和字号。右上角“字号”可选择 80%、100%、120% 或 140%，选择仅保存在当前浏览器，刷新与切换页面后仍保留；主要文字和指标加粗显示。

集群采集复用 [Backstage 集群工具](../cluster/README.md)，通常每 5 秒更新机器资源、
每 30 秒检查已配置的端口/健康入口；GPU 连续采样每 0.5 秒读取并汇总最近 60 秒窗口，
单次回退单独标为瞬时值，不计入窗口活跃卡统计。
采样节奏与端口检查须先在本机配置并显式启动服务，未启用时页面显示未配置或暂无快照。
CPU、内存、GPU 指标与机器不可用状态分别显示；分组和名称来自本机配置。

所有内容都在现有 8787 页面内渲染，没有独立 8790 网页或 iframe。SSH 别名、可选端口检查
以及旧服务的手动切换步骤见 [配置与迁移说明](../cluster/README.md)。

更新代码后，已有 Web 后端须在明确部署时重启，才能提供新增的静态资源与只读 `/api/cluster`。
旧进程即使读到磁盘上的新版版本号，也可能对这些路径返回 404；更新源码不代表服务已加载新版。

## 保留的检索与交接接口

原有 `/api/events`、`/api/event`、`/api/context`、`/api/handoff` 和 `/api/documents` 保留，供已有工具和按需查证使用。事件及文档检索仍复用 CLI 的词法匹配与本机 `search_aliases`；事件上下文返回有上限的邻域与修正链。前端首页不再列出原始记忆或独立交接列表，关键节点可以按需展开其内容、来源位置、验证依据及后续状态/修正。

项目与任务时间线只读，不领取、关闭或恢复任务。关闭和普通后续进展分别处理，状态冲突保留为冲突，不按时间选赢家。连续打开来源时仅显示最后一次选择，关闭抽屉后不填入迟到响应；节点和依据的日期采用 UTC。

## 本机自检与运行版本

“监控 → 本机服务”复用 `memory doctor`，检查配置、数据、链接、同步基线与冲突，不连接 S3，不读取服务凭据或修复链接。同步基线和冲突读取 `--local-root`，页面标明本机范围及采样时间。

自检展示记忆健康候选明细（最多 50 项）、核心 Git/版本与 Skill 最低版本声明。有来源的候选可以按需查证；候选问题不等于事实失效。

服务卡片读取 PID 记录中的启动源码身份并与工具核心磁盘版本比较。旧进程缺少启动证据时显示未知，未提交改动也不能证明运行内容一致。训练采集失败、超时、缺失或无效 JSON 明确显示不可用，成功空列表才归为无数据。
