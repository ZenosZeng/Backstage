DAILY WORKFLOW

配置一次，日常用对话推进。

在已接入入口规则与 Skill 的工作区中，让 Agent 按约定读取和记录上下文。CLI 用于初始化、维护与排障。

01 · 接着做

“回顾这个项目的状态、最近决策和未完成事项，再继续。”

按项目与任务读取相关记录，核对当前代码和环境，减少跨会话重复交代。

02 · 留下依据

“记录这次修复的原因、验证结果和下一步。”

结构化记忆保留来源和状态；项目知识承载摘要，Markdown 与 SVG 文档保留完整叙述。

03 · 检查与交接

“看看机器资源，并准备给下一位 Agent 的任务交接。”

查看带采样时间的资源快照；按任务整理决策、验证和会话来源，交接材料准备后再派发。

项目时间线 ↗项目文档与进展 ↗八卡资源面板 ↗

工作台按项目 → 任务 → 证据组织信息。任务关闭不等于项目完成，运行观测不等于业务状态；缺少依据时明确显示未知。

FEISHU REMOTE CONTROL

不在终端前，也能继续协作。

飞书桥接连接本机 Agent CLI。配置后私聊直接发任务，群聊 @机器人；网页保持只读，遥控在飞书中完成。

一条消息，接上当前工作。

发送“检查这个仓库的测试，说明失败原因”，机器人在当前目录调用 Agent，并更新同一张进度卡片，显示动作、近期输出和执行结果。

  • Claude 与可选 DSH 分别保留上下文；聊天之间隔离目录、队列和会话。
  • 执行中用 /queue 排队，或发送“停止”打断；任务结束后查看结果与耗时。
  • 待决策问题通过 /questions 查询、/answer 回复。收到通知不等于授权执行。

首次接入需要飞书应用凭据、用户白名单、已登录的本机 CLI 和明确权限档；默认只读。凭据留在本机，权限配置决定 Agent 可以执行哪些操作。

配置与完整命令说明 ↗
/status当前 Agent、目录、上下文与队列
/claude · /dsh切换执行器，分别保留会话
/cd <目录>切换当前聊天的工作目录
/queue <任务>排队执行，上限 5 条
/questions列出本机待决策问题
/answer <id> <回答>写回问题答案，供 Agent 继续处理
/new重置当前执行器上下文及待执行队列
/help · 停止查看帮助，或打断当前任务

飞书遥控、watchdog 状态通知和交互提醒分别配置。静态 Demo 只展示合成数据，不连接飞书、不派发任务。

START SMALL

先在本地，
留住下一次上下文。

完整工具环境支持 Linux x86-64。准备 Git 与 Pixi，在全新工作区完成一次初始化，再打开只读工作台。

查看完整初始化说明 ↗

已有工作区请沿用原配置。初始化前先预检入口冲突；S3、监控与飞书均按需独立配置。

新工作区 / Terminal
git clone https://github.com/ZenosZeng/Backstage.git ~/code/.agents
cd ~/code/.agents
pixi install --locked

# 先预检，确认无冲突后再初始化
python3 scripts/sync.py --dry-run init --local --machine-id my-dev-machine
python3 scripts/sync.py init --local --machine-id my-dev-machine

pixi run web
随后打开 http://127.0.0.1:8787前台运行 · Ctrl+C 停止
